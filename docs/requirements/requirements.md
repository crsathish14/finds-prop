### Source-of-truth ranking applied

1. **UX** defines how things look and behave visually.
2. **ANA** defines what existing features do and the verified rules.
3. **ARC** defines the stack and the decisions it lists as "Decided". Where ARC _changes functionality_ (for example sign-in), ARC wins and the affected UX screens are listed as UX deltas (`DEC-04`).
4. Security and correctness requirements are added where all three are silent (§6, `07-security-and-permissions.md`).
5. Unresolved conflicts are recorded in `02-architecture-review.md` §5 (`C-*`) and `12-open-decisions-and-risks.md` (`DEC-*`).

## 3. Requirement IDs and status labels

IDs are `FR-<module>-<nn>`. Modules: `PUB` public discovery, `GEO` location and maps, `AUTH` authentication, `ACC` account (buyer and seller), `BLD` builder portal, `ADM` admin portal, `SYS` cross-cutting platform, `PG` paying-guest and hostel listings.

| Status          | Meaning                                                                                |
| --------------- | -------------------------------------------------------------------------------------- |
| **EXISTING**    | Verified in ANA (DEMO behaviour). Rebuild faithfully.                                  |
| **DECIDED**     | Not in DEMO, but ARC "Decided on 29 October" commits to it. Build.                     |
| **PROPOSED-UX** | Designed in UX as _Proposed_; not decided in ARC. Build only after approval (`DEC-*`). |
| **NEW-GAP**     | Required by ARC but **not designed** in UX. Needs a UX addendum before UI work.        |
| **DEFERRED**    | Explicitly out of the first release. Not planned in detail.                            |
