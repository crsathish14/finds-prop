# UX reference

Index from routes to the approved UX screens. States are selected with a URL hash in the prototypes (for example `screens/auth-otp.html#wrong`); the full state list of each screen is in `docs/ux/final-ux/screen-inventory.md` and, for the addendum, in `docs/ux/ux-addendum/assets/manifest.js`. Behaviour and visual rules: `docs/ux/final-ux/design-system.md`, `interaction-specifications.md`, `navigation-and-information-architecture.md`.

The addendum screens (`docs/ux/ux-addendum/`) replace or extend the approved screens named in the plan for sign-in, address, map, legal, sponsors and localities. They were designed by Claude on 30 Oct 2026 and are marked **Proposed** until the owner approves each one. **A proposed screen is not built until approved** (R-DS-06).

## Design system boards

The five approved design-system boards are built in the Design Lab (ADR-020) with the real components, and a sixth board, **Domain**, shows the organisms that appear only inside the screens (property, project and developer cards, search, filters, gallery, enquiry; S4-T01). The approved UX has no board for them: their look is in the search, property, projects and home screens, so the Domain board mirrors those. A seventh board, **Discovery**, shows what spans the screens when choosing homes and projects: the compare bar and the comparison (S4-T02), the projects page and the project page (S4-T09), and the signed-in dashboard (S5-T04), mirroring the compare, projects, project and dashboard screens. Open it with `DESIGN_LAB=1` and go to `/design-system`. Each entry on a lab page names the component files it shows; the list of entries is `src/design-lab/registry.ts`, and a test fails if a shared component has no entry.

| Lab page                     | UX board                                       | Shows                                                                                                                                                                                                     |
| ---------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/design-system/foundations` | `docs/ux/final-ux/screens/ds-foundations.html` | Colour with measured contrast, type, spacing, shape, elevation, focus, icons, layout helpers                                                                                                              |
| `/design-system/components`  | `docs/ux/final-ux/screens/ds-components.html`  | Buttons, links, fields, form fields, combobox, upload, chips, badges and statuses, card parts, sortable rows                                                                                              |

## Site header, footer and bottom bar (S4-T06)

The layout components of the `ds-navigation` board are mounted by the route groups in `src/app/[locale]/`, from `src/features/site`. The content comes from the site settings (header and footer; the catalogue links are used while they are empty, BR-81) and the feature flags (a link to `/ai-search` is absent while `FLAG_AI_SEARCH` is off).

| Route group | Pages                                                                              | Header                                       | Footer | Bottom bar (phones)                                                                 |
| ----------- | ---------------------------------------------------------------------------------- | -------------------------------------------- | ------ | ----------------------------------------------------------------------------------- |
| `(public)`  | home, search, projects, property and project detail, compare, contact, legal pages | yes                                          | yes    | only on home, search, projects, compare, AI search and contact; not on detail pages |
| `(account)` | dashboard, post a property                                                         | yes                                          | yes    | only on the dashboard                                                               |
| `(auth)`    | customer and builder sign-in, reset password                                       | yes                                          | yes    | no                                                                                  |
| `(quiet)`   | administrator sign-in (ADD-06)                                                     | yes                                          | no     | no                                                                                  |
| `(portal)`  | admin and builder portals                                                          | the portal shell (S7), not the public header | no     | no                                                                                  |

Pages that call `notFound()` or fail while they render show the header and footer around the message (a `not-found.tsx` and `error.tsx` in each group), and the phone bottom bar, which error pages ask for because they keep the address of the page that failed. A URL that matches no route at all shows the plain not-found screen (`global-not-found`), which has no layout in this Next.js version.

Not yet built: the notification bell (Proposed), and the saved and enquiry counts (Stage 5).
