# ADR-184 · The poster's private contact email for enquiries (enquiry mail, part 2)

- Status: Accepted for part 2 (the address and where it is asked). The mail itself is part 4 of the plan; nothing is sent by this change. The new words await the owner's approval.
- Date: 2026-11-24
- Related: ADR-181 (the Resend sender, part 1), ADR-010 (the reserved admin addresses), ADR-017 (column grants), ADR-060 (listing submit), ADR-138 (the location rule of `submit_listing`), R-BE-10 (no personal data in logs), the plan `ENQUIRY_EMAIL_PLAN.md` (outside the repo)
- Class: C2 (one migration, a new write path for a private personal field). Plan approved by: owner, 24 Nov 2026.

## Context

The owner wants the person who posted a home to be told by email when someone enquires (ADR-181). A home owner signs in by phone and has no email on the account, so there is nowhere to send it. Project leads already have `builders.email`. Homes need an address kept for this one purpose.

This is **not** the sign-in email of `FLAG_CUSTOMER_EMAIL` (ADD-03): that flag, `getEmailState` and the steps in `src/features/auth` are untouched. The two can differ, and this address is never used to sign in.

## Decision

- **One new column, `profiles.contact_email`** (nullable text). A check holds it to at most 254 characters, all lower case, and shaped like an address: something, one `@`, something, a dot, something, no spaces. Empty is stored as null.
- **Private by the rules that already exist.** `profiles` is readable by its own person and the super admin (`profiles_select_own`, `profiles_select_admin`); the table-level `select` grant covers the new column; `anon` has no grant on the table. The `update` grant stays `full_name` only, so nobody can write the column with an `update`. No public function, view or search returns it. It is never public, never in an enquiry row, never in a URL.
- **One controlled write path: `set_contact_email(p_email text)`**, SECURITY DEFINER with an empty `search_path`. It uses `auth.uid()` (it can only change the caller's own row), needs a verified phone like every other owner write (`has_verified_phone()`), trims and lower-cases, stores null for an empty value, refuses a value that is not an address or is over 254 characters (`profile.contact_email_invalid`, SQLSTATE 22023), and refuses the reserved admin addresses with `is_reserved_admin_email` (`profile.contact_email_reserved`, so a person cannot use the platform's own admin address; the screen shows the same words as for an address that cannot be used, so the list is never revealed). It answers the address as stored. Execute is granted to `authenticated` and `service_role`, revoked from `anon` and `public`. **The service role is not used**: the action calls the function as the signed-in person, so no row is added to the allow-list in `docs/engineering/security.md`.
- **The action path.** `saveContactEmail` (dashboard) and the `contactEmail` that rides with `submitListing` (wizard) both call `set_contact_email`. `saveContactEmail` needs a verified phone and is limited with the existing `project_save` scope (60 an hour a user; no new scope). The address is in no log line and no error text (the logger masks email values); the log line says only that it was saved.
- **Wizard (`src/features/listings`).** A required "Email for enquiries" box on the last step, next to Submit, started from the address the account already holds, so it is typed once and reused on the next home. It is not one of the draft's fields: Continue and Save draft never send it and never need it, so a draft saves without it. It is not kept in the browser for the way back in after a session ends. The rule "a listing cannot be sent without it" lives in `sendForReview`: an address sent with the submit is saved first; with none, the account must already hold one, or the listing is refused with a problem on the `contactEmail` field and stays a draft. A listing that was rejected and is sent again asks too; one in review or Live that is only edited does not.
- **Dashboard.** A card above the tabs for an owner who has at least one home outside the drafts: "Add your email to get enquiries by email" with a box and Save when there is none, and the saved address with a Change button when there is one. New design-system part `ContactEmailCard` (Design Lab, Seller board); the connected `ContactEmail` is in `src/features/account`.
- **Existing owners.** Homes already posted have no address. Their owners get the prompt on the dashboard, and **no mail is sent for their homes until they add one** (part 4 skips a poster with no address; their enquiries still show in the dashboard).
- **The address is not verified.** Nothing is sent to it to check it, and the screens say so. Nobody can stop a typing mistake or another person's address being given.

## Consequences

- **A mistyped address bounces.** Too many bounces can make Resend pause the account, and mail to someone else's address tells them about an enquiry. Mitigation for now: the saved address is shown back on the dashboard and the hint says it is not checked. Part 4 only logs a failed send; a bounce webhook is a later change if bounces happen.
- **Privacy.** The address is personal data held for one purpose. It is read only by its owner, the admin and (in part 4) the mail module acting for the server. It must never go into a log line (mask it: the logger already masks email values), an error message, an audit entry, a URL or an AI tool result. The privacy policy page already names Resend as a processor.
- **Posting needs one more field.** A new owner types an email once; the next home starts with it filled.
- **Tests:** a database test file (`profile_contact_email.test.sql`: set and read their own, another person cannot read or change it, a visitor can do neither, the admin can read it, the format, length and reserved addresses are refused, no direct update); the function list test now names the new function; unit tests for the schema, the wizard rule, the action, the query, the card and the dashboard page; integration tests for the real submit and the privacy of the column.
- **Rollback:** nothing reads the column until part 4. `drop function public.set_contact_email(text); alter table public.profiles drop column contact_email;` undoes the database half; the wizard box and the dashboard card are then removed with the code. After part 4 merges, fix forward instead.
