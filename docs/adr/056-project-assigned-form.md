# ADR-056 · A project's assigned form (S5-T05, fourth change)

- Status: Accepted. File uploads (the third change) were skipped by the owner on 6 Nov 2026, so this is the last change of S5-T05.
- Date: 2026-11-06
- Related: ADR-046 (the project page and its enquiry card), ADR-054 (the forms backend), ADR-055 (the renderer and the contact page), ADR-048 (cache tags), FR-PUB-09, FR-ADM-08, BR-49, BR-60 to BR-63, BR-94
- Plan approved by the owner on 6 Nov 2026, "All recommended": the chain starts with the form the admin chose for the project, the rate limit is the existing `form_submit`, and a form that cannot be shown falls back to the built-in card without a notice.

## Decision

- **Which form a project page shows (BR-49), first match wins:** (1) the form the admin chose for the project (`projects.form_id`), when it is active and shown somewhere (placement other than "none"); (2) an active form made for this project alone (placement `project_specific`); (3) an active form shown on every project page (placement `project`); otherwise the built-in Enquire / Site visit card, which is unchanged. The most recently edited form wins a tie inside a tier.
- **`public_project_form(slug)`** (migration `20261106150000_project_form.sql`) follows that chain in the database, because visitors cannot read `projects.form_id`. It is a `security definer` function that visitors may call. It returns only the columns a visitor may see (never the CRM link), and nothing for a project that is not approved, published and of an active builder (BR-94). `getProjectForm(slug)` reads it as an anonymous visitor, cached for minutes under the `forms` tag. No form assigned is the normal case and is cached like any answer; a failed read or fields that do not fit are logged by code, kept for seconds only, and give no form.
- **A form that cannot be shown never loses the enquiry:** the slot falls back to the built-in card (no "could not load" notice, owner decision). An assigned form is drawn only after the sign-in check, so a visitor without a verified phone sees the same gate as today.
- **`submitProjectForm`** is a new action with `auth: "verified-phone"`. The request carries the project's slug, the answers and a one-time key, and nothing that names a form or says who is sending. The server finds the form again by the project (never one named by the request), checks the answers against its stored fields (BR-60), and **replaces the mobile with the signed-in account's own phone** (`verifiedPhoneDigits`, moved to `src/server/auth/verified-phone.ts` so both features share it; the form's own `mobile` field is filled from the account, so the visitor is never asked for it). The source stored is the project's own address. The existing limit `form_submit` applies, 5 per visitor per hour, counted for the project's page (key `project-<slug>`). Name and phone still mirror into `project_leads` for an enquiry, brochure or site-visit form (BR-63).
- **`record_form_submission` has one more case** (same migration, `create or replace`, privileges unchanged): a form chosen through `projects.form_id` may have any placement, so the project the page names counts when it has chosen that very form; any other project is ignored, as before.
- **Renderer:** `DynamicForm` gets `compact` (one column at every width, for the narrow card) and `locked` (fields shown read-only with a value from the page, such as the masked phone; the value is not sent). `ConnectedForm` takes either `send` (the contact page) or `sendProject` (a project's form, which sends the project instead of a form slug), plus an `intro` shown until the form is sent. `ProjectAssignedForm` puts it in the existing card shell (`ProjectFormCard`, with `LEAD_CARD_FRAME` shared with the built-in card), with the card's heading and consent line, and `ProjectFormSent` (the form's own success text, else the card's words).
- **Cache:** the admin form builder (Stage 7) must call `tagsAfterFormChange` when it saves a form and when it changes a project's `form_id`; until then the page shows a change within a few minutes.

## Consequences

- The enquiry card now has two shapes. The built-in one is untouched when no form is assigned, which is every project today (the dev database has no forms placed on projects).
- All visitor-facing words are reused from the built-in card (title, phone hint, consent, thank-you). The form's own labels, button and success text are the content team's data.
- Not tried against a real database here (no Docker): `project_form.test.sql` (16 checks) and the new case in `tests/integration/forms.test.ts` run in CI. A live check needs a project with an assigned form and a phone sign-in, which are the owner's.
- Not built: file uploads (skipped), the admin form builder and its CRM delivery (Stage 7), and the Call, WhatsApp, brochure and shortlist events.
