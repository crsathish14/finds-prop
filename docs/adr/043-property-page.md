# ADR-043 · The property page (S4-T03)

- Status: Accepted (data layer); the page is added by the next change
- Date: 2026-11-05
- Related: ADR-025 (SEO and URLs), ADR-012 and ADR-042 (search and results), ADR-017 (public projections), `docs/ux/final-ux/screens/property.html`, FR-PUB-07, BR-90, BR-92
- Plan approved by the owner on 5 Nov 2026 ("All recommended"): step A (this data layer), step B (the page), step C only if the signed-in form needs its own change. The traceability table names this task S4-T08; the owner calls it S4-T03.

## Decision for step A: the data layer (`src/features/property`)

- **The address** is `/properties/{slug}-{shortId}` (ADR-025). `parsePropertyAddress` reads the last eight characters as the public id (the 32-letter alphabet the database checks, no 0, 1, i, l or o) and the slug before them; capitals are read as lower case; anything else is "not found". `canonicalPropertyPath` gives the address a home should have when the one given differs (an old or edited slug, capitals): the page redirects with a 308 and a link with the right id never breaks.
- **One cached read of one home** (`getProperty`) as an anonymous visitor, so the database's own rules decide what exists (BR-90): only approved listings, only the granted columns. The owner, the address, the pincode and the exact location are never asked for, and a test fails if they are. The photos come from `listing_media` (the cover first, then the owner's order), and the label from the database's own `listing_label()` (BR-92), so there is one source for it.
- **"Missing" is not an error.** No approved home with the id is `missing`, which covers a home never listed, one waiting for review, and one sold or rented. Anything else that goes wrong throws and is never cached: a failed read must not look like a home that is gone, and a row that does not fit what the page expects is a failure, not "not found". Errors are logged by their code only.
- **Cache:** minutes, under the homes tag (`home-listings`), so an approval or an edit refreshes it.
- **Pure rules, no words** (`view.ts`): the facts for "At a glance" in the UX order and only when given (bedrooms are also left out for a plot, a commercial property and a count of 0), the price per square foot for a sale only and only with a known area, the description as paragraphs of plain text (a blank line starts one; never HTML), the amenities as the owner wrote them (trimmed, none empty, none twice), whether a detail the owner may leave out is missing (bathrooms, furnishing, amenities: "available from" is not drawn, so it does not count), the place line, and the page description (the first paragraph, cut at a word). The page turns these into text.

## Consequences

- The page (step B) adds no query of its own.
- Not tried against real homes: the hosted dev database needs secrets, so the read is tested with a stub client.

## Decision for step B: the page (`/properties/[slug]`)

- **Composition:** `app/[locale]/(public)/properties/[slug]/page.tsx` parses the address, reads the home (`getProperty`), sends a known id with another slug to the canonical address (308) and gives `PropertyScreen` the home, the photo addresses (built from public storage) and two slots for the enquiry. `PropertyScreen` fetches nothing and holds no state, so the Design Lab draws every state with sample homes. Title and description of the page come from the home (`generateMetadata`).
- **Screen** (as `property.html`): breadcrumb Home > Properties > locality (the UX draws the last crumb as a link; the shared breadcrumb makes it the current page), "Back to results" below 1024 px (to `/properties`), the gallery with For sale or For rent and the label, the title and "Velachery, Chennai · Listed 2 days ago", At a glance, About this home, Amenities, and from 1024 px the price card, the enquiry card and the note "Only approved homes are listed on Find Prop." A phone has the sticky bar and the enquiry sheet instead (this page is not in the bottom bar's list, as the UX has it). Anything the owner did not give is left out; the note that optional details are left out shows only when bathrooms, furnishing or amenities are missing. No Save or Add to compare buttons until S5-T01 and S4-T02 (owner's answer).
- **The enquiry is read behind its own Suspense boundaries** (`EnquiryPanel`, `MobileEnquirySlot`), so who is signed in never holds back the photos and the details; the card has a skeleton while it waits. A visitor with no session, or one that cannot be read, gets the gate. The gate's links ask sign-in to come back to this home (`/auth?gate=enquire&redirect=…`, the address only).
- **Signed-in visitors, before enquiries can be sent (owner's answer 1):** the real form with Send switched off and the line "Sending enquiries is not open yet." (`sendDisabled` and `sendNotice` on `EnquiryCard`, both off by default). The plan said "with full validation": with Send switched off nothing can be submitted, so the validation, send-failed and sent states (already built into the card) arrive with the action (S5-T03).
- **Not found:** an address that is not a slug and an id, and an id no approved home has (never listed, in review, sold, rented, withdrawn), give the UX's "Property not found" with the one next step "Browse all properties". **The plan said "with a real 404", which this cannot give:** the page streams under its loading screen, so by the time the home is known the response has already started with status 200, and Next.js adds `noindex` to it instead. The screen is correct and search engines are told to leave it out; a true 404 would need the read to finish before anything is sent, which means no loading screen and no static shell for this route. Not changed without the owner.
- **Shared components touched:** `EnquiryCard` (the two options above) and `EmptyState` (accepts an h1, for a page with no other heading); the defaults do not change.
- **Words** (new, for the owner's approval, in `en.json` under `property.page`): the facts' labels, "At a glance", "About this home", "Amenities", the furnishing words ("Unfurnished", "Semi-furnished", "Fully furnished"), "{title}: photo {number}" (a photo the owner did not describe), "{place} · Listed {ago}", "Listed {ago}", the left-out note, "Back to results", "Sign in to enquire", "Enquire", "Sending enquiries is not open yet.", "Property not found" with its text and "Browse all properties", "Loading property".
- **Not built:** sending enquiries (S5-T03), Save and Compare, the canonical `<link>`, JSON-LD and the sitemap, similar homes, a map, view tracking. Not tried against real homes: the hosted dev database needs secrets, so the read is tested with a stub client and the page was exercised with no database behind it (not-found and failed-read screens) and with sample homes in the Design Lab.
