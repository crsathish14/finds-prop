# ADR-133 · Place search route `GET /api/places/autocomplete`, part 3 (S4-T05 reopened)

- Status: Proposed. Built in this change; the owner approves before it merges. No page calls the route yet (the search box is a later change).
- Date: 2026-11-17
- Related: ADR-131 (the adapter), ADR-132 (the screens and states), ADR-013 (provider adapters), ADR-128 section 7 (the rate-limit scopes), R-BE-08, R-BE-09, R-BE-10, R-SEC-02, FR-GEO-01 criteria 1 to 5, DEC-31, `OLA_MAPS_PLAN.md` sections 4.1, 4.2 and 4.8 (row 3 of the table of changes)
- The owner approved the overall plan on 17 Nov 2026. The numbers of the address limit below are a proposal in that plan ("a per-IP burst limit") and are the owner's to change.

## Decision

- **One route, one concern.** `GET /api/places/autocomplete?q=` is the browser's only way to get place suggestions. The browser never sees the key and never calls the provider. The route file (`src/app/api/places/autocomplete/route.ts`) only composes: it reads the region from the site settings (a route under `src/app` may compose features; the server layer never imports one) and the server configuration, and hands both to `handlePlaceAutocomplete` in `src/server/places/autocomplete-handler.ts`, which holds every rule and takes its dependencies as arguments so it is tested with the fake provider and no network. GET is the only method exported (the framework answers 405 to the rest). There is no `/api/places/details` route: every suggestion carries `lat` and `lng` (ADR-131).
- **Steps in a fixed order, as in `defineAction` where they apply:** parse `q` (400), rate limit (429), provider and region, look up, answer. Input is checked before anything is counted, so a malformed request spends no limit and no provider call; the limit is counted before the settings are read and before the provider is asked.
- **Input.** `q` must be given exactly once, contain no control character (a line break, a tab, a null byte, a line or paragraph separator; checked before trimming), and be 3 to 80 characters after trimming, counted as a person counts them (code points, not UTF-16 units). The bounds are the adapter's (`PLACE_TEXT_MIN_CHARACTERS`, `PLACE_TEXT_MAX_CHARACTERS`). The trimmed text is passed on unchanged: the "K K Nagar" cleanup stays in `resolvePlace`, which the Search button uses.
- **The answer** is the `ActionResult` envelope (`{ ok: true, data }` or `{ ok: false, code, … }`) with `Cache-Control: no-store` and the request id in `x-request-id`, on every status. On success `data` is the list of `{ id, label, detail, kind, lat, lng }`, exactly those six fields (anything else the provider sent is dropped), possibly empty. The shapes are in `src/types/places.ts`, so the later search box imports them.
- **A failure that is not the visitor's mistake carries `reason`, for the box's states** (ADR-132): `unavailable` (the provider timed out, failed, is switched off by `PLACES_DISABLED` or is not configured, or our side failed) and `limited` (our own limit, or the provider's quota). The box reads `reason`; the status is for monitors and caches.

  | Case                                                            | Status                                   | `code`            | `reason`      |
  | --------------------------------------------------------------- | ---------------------------------------- | ----------------- | ------------- |
  | `q` missing, short, long, repeated, or with a control character | 400                                      | `VALIDATION`      | none          |
  | our own limit (per visitor or per address)                      | 429, with `Retry-After` and `retryAfter` | `RATE_LIMITED`    | `limited`     |
  | provider quota (`quota`)                                        | 503                                      | `UPSTREAM_FAILED` | `limited`     |
  | switched off or not configured (`off`)                          | 503                                      | `UPSTREAM_FAILED` | `unavailable` |
  | provider timed out or failed (`timeout`, `error`)               | 502                                      | `UPSTREAM_FAILED` | `unavailable` |
  | anything else (the counter, the settings read, a bug)           | 500, with the request id                 | `INTERNAL`        | `unavailable` |

  The rate-limit counter failing is refused, not waved through (fail closed, as for every anonymous limit), and the box degrades to typed text like for a provider failure.

- **Rate limits: the existing `places` scope gets a second rule; no new scope and no migration.** The visitor rule stays 60 a minute (a browser, told apart by address and browser). The new rule counts one address, with an IPv6 address cut to its /64 prefix (the `network` kind of ADR-128 section 7.1), at **30 in 10 seconds**. One browser is held by the first rule, so the second meets only a client that changes its browser identity on every call to get round the first: it cannot burn the provider quota, and a visitor on another address is never counted with it. A person who types makes about one call a second at most (the box waits 300 ms and sends at three characters), so a shared address (a campus, a mobile carrier's NAT) stays well under 30 in 10 seconds. The database scopes are `places_visitor` and `places_network`; the column's check (`^[a-z][a-z0-9_]*$`, at most 40 characters) already allows them, so no migration is needed. The rows are swept after 7 days like every other scope. There is still no daily ceiling that could switch place search off for everyone (ADR-131); the owner's levers are the usage count (a later change), this burst limit and the kill switch.
- **Nothing private is logged, stored or returned.** The typed text, the place names and the provider's request address (it holds the key) are never logged or put in a response (R-BE-10). A lookup that failed logs one line with only the failure class (`timeout`, `quota`, `error`; `off` is a debug line, not a fault), a refused call logs the scope, and an unexpected error logs only the error's class name and goes to the error tracker (ADR-130). Every line carries the request id. The response to a failure never holds a provider message.
- **Nothing is cached or stored.** The route is dynamic (`connection()`), the answer is `no-store`, no suggestion is written anywhere, and no place id is kept (ADR-131). The usage count is a later change.
- **The route is public and read-only,** so it needs no session, signature or cookie, and it needs no row in the service-role list (the rate-limit counter is already on it).

## Consequences

- The search box (a later change) fetches this route, sends nothing but `q`, and reads `ok`, `data`, `reason` and `retryAfter`.
- Any visitor can make at most 60 calls a minute and an address at most 30 in 10 seconds; the real Ola calls are fewer still, because a request is refused before the provider is asked. A quiet bot that stays under both limits is still possible: that is what the usage count and the kill switch (`PLACES_DISABLED=1`) are for.
- `docs/engineering/security.md` lists the second rule in the rate-limit table; `docs/ux-reference.md` no longer lists `/api/places/details`.

## Verification

Unit tests, with the fake provider and no network (`src/server/places/__tests__/autocomplete-handler.test.ts`, `src/app/api/places/autocomplete/__tests__/route.test.ts`): success with exactly six fields, an empty list, trimming, the 3 and 80 character edges, every kind of bad input (missing, empty, short, spaces only, long, line break, tab, null byte, separator, repeated `q`) refused before any count or call; the limit counted before the provider; 429 with the seconds to wait; a failing counter; each `PlaceLookupError` class and its status and `reason`; the kill switch and an unconfigured production; an unexpected error; `no-store` and the request id on every answer; no typed text, place name or key in any log line or response, on any path. The rules of the scope are checked in `limits.test.ts` and `enforce.test.ts`. `tests/integration/rate-limit.test.ts` has three cases against a real database (the address burst stops a client that changes browser on every call, a visitor on another address is never counted with it, one browser is stopped at 60); they run in CI only, and were not run by the author (no Docker, by the owner's rule). The real service is exercised only by the owner's live run of 17 Nov 2026 (ADR-131).
