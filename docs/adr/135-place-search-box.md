# ADR-135 · Place search box: the home search card and the results Locality field (S4-T05 reopened, plan PR 4)

- Status: Proposed. Built in this change; the owner approves before it merges. This is the first change where a visitor reaches Ola Maps (through the route of ADR-133).
- Date: 2026-11-17
- Related: ADR-131 (the adapter), ADR-132 (the screens and the wording of the panel, approved 17 Nov 2026), ADR-133 (the route), ADR-134 (the usage count), ADR-040 and ADR-042 (the search address and the results page), ADR-053 (the legal pages), FR-GEO-01 criteria 1 to 5, FR-GEO-03 criteria 1 and 2, `OLA_MAPS_PLAN.md` (outside the repository) sections 4.2, 4.3 and row 4 of the table of changes
- Class C1 (a feature inside existing patterns). Plan in the pull request.

## Decision

- **One hook for the browser side of the route.** `usePlaceSuggestions(text)` (`src/features/search/use-place-suggestions.client.tsx`) is called from the Combobox's `onQueryChange`, so the Combobox's own three-character minimum and 300 ms pause apply. It asks `GET /api/places/autocomplete?q=<text>&source=search_box` with `fetch` and an `AbortController` (a newer question cancels the older one; so does text under three characters and the box going away). TanStack Query is not used and nothing is added to `package.json`. It returns the Combobox options (`value` = the provider's id, `label`, `description` = the rest of the address), the panel `state` for `usePlacePanel` (`ready`, `loading`, `empty`, `unavailable`, `limited`), `pick` (finds the suggestion behind an option, so its point is kept) and `picked`.
- **How an answer becomes a state.** A list with no usable item is `empty`; the route's `reason: "limited"` is `limited`; a network failure, an answer that is not JSON or not in the shape of ADR-133, and every other failure is `unavailable`. One extra rule: `VALIDATION` (text the route refuses, such as more than 80 characters) is `empty`, so the box offers the keyword row instead of saying that place search is down. Rows that are not suggestions (a missing name or point) are left out, and a repeated id is shown once.
- **The panel never shows the answer to other text.** From three characters until the answer for exactly that text arrives the state is `loading` and the old suggestions are hidden, so Enter can never pick a suggestion for text that is no longer in the box. A text equal to the picked name asks nothing (the Combobox puts it in the box and would ask for it after its pause) and keeps its list.
- **Home page (`HomeSearch`).** The locality box uses the hook, `usePlacePanel`, three characters and the default pause. Picking a suggestion makes Search go to `/properties?place=<name>&lat=&lng=` (the default radius is left out by the address contract). Pressing Search without a pick, or after the picked name was edited, sends the text as `locality=<text>`, as before. A typed name that is one of the curated localities is that place with its own point and radius, as before, even if a suggestion of the same name was picked (`searchParamsFromCard(values, curated, picked)`). The curated localities stay as the Popular chips.
- **Results page.** The Locality field of the filter rail and the phone sheet is the same box (`PlaceBox`, `place-box.client.tsx`). Picking a suggestion sets `place`, `lat`, `lng` and keeps the radius the address already has; the keyword row, or Enter on typed text, sets `locality` (a text match); emptying the box or the clear button takes the place, its point and the radius off. On the rail typing alone changes nothing (every change reloads the results); in the sheet the typed text is part of the draft at once, because nothing applies until Show. While the box holds the place already chosen it opens no panel and asks nothing. The box shows a place that changed from elsewhere (a chip removed, Clear all). In the Design Lab the filters keep their pictured Locality list (`preview` in the navigation context), so no Lab picture changes and nothing there calls the route.
- **Search is never held back (FR-GEO-01, criterion 3).** Unavailable and limited are states of the panel with the Lab's notes; the keyword row (unavailable and empty) searches the typed text, Enter and the Search button always work, and nothing is disabled.
- **Small, additive changes to the design-system parts, none of which changes a picture:**
  - `SearchCard` gains the optional `onLocalityTextChange` (every change of the text, before the pause; `usePlacePanel` words the panel by the text and the card keeps it private) and `onLocalitySelect` (the suggestion chosen, so the host keeps its point). It also marks the keyword row as chosen when Enter picks it, so Enter on the keyword row searches once, not twice (a fault that only showed once a page used the keyword row).
  - `FilterFields`, `FilterRail` and `FilterSheet` accept `placeField` as a node (as before) or as a function of `{ id, values, onChange }`. The sheet keeps its choices in a draft, which a node cannot reach; the function lets the box set the locality and its point in the draft. `FilterValues` gains the optional `point`.
  - The search feature's `searchHrefFromCard` takes an optional picked place; `searchFromFilterValues` turns a locality that has a point into a place with that point and the address's radius (before, a place that was not curated became a text match on the next filter change and lost its point).
- **Privacy.** The privacy page's "Who we share it with" section says that the text typed in a place search box is sent to Ola Maps to find matching places and that nothing else about the visitor is sent. The box's panel already carries the credit line (ADR-132); the sentence about what is sent is the privacy page's. The page is a placeholder with a draft notice (ADR-053) and its text is in `content/privacy.ts`, not `en.json`; the new paragraph is the only sentence there that is not in brackets. **Legal wording: the owner to confirm.** Nothing is said about how long Ola Maps keeps anything: that is not verified.

## Decisions for the owner

- **Curated localities are not listed as options while typing.** Before, typing one letter listed the curated localities that matched. The place panel opens only from three letters and its rows are place rows, so a curated name (a plain row) among them would be a design the owner has not approved. They stay as the Popular chips, and typing a curated name exactly is still that curated place. If the owner wants matching curated names listed first, that is a small follow-up.
- **The keyword row is not drawn for "too many searches".** `usePlacePanel` gives it for `empty` and `unavailable` only, as approved in ADR-132; for `limited` the note says to wait and Search or Enter still searches the text. Changing that would change the Lab's "too many searches" picture.
- **No picture changes in the Design Lab.** The Lab's filters keep the Locality list (`preview`), and `SearchCard` draws as before. Nothing here needs new baselines; the real pages are not in the screenshot suite.

## Consequences

- Typing three characters in either box now calls `/api/places/autocomplete`, which is rate limited (ADR-133), counted (ADR-134) and can be switched off with `PLACES_DISABLED=1`. With the route off or failing, both boxes behave as plain text fields with the Lab's message.
- The text typed is sent to our route and from it to Ola Maps and nowhere else. Nothing is stored in the browser or the address: only a picked place's name, point and the radius are in the address, as for a curated place.
- A page that gives `placeField` as a node keeps working unchanged; the Lab's examples do.
- Left to later changes (plan): the radius chips and "Also near" on the results page (PR 6), the distance sort and `search_properties()` (PR 5), the listing location (PR 7), the admin pickers (PR 8), and the full-screen sheet for phones (not built in ADR-132).
