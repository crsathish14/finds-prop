# ADR-131 · Place search provider adapter (Ola Maps), part 1 (S4-T05 reopened)

- Status: Proposed. Part 1 (the adapter, no screen) is built in this change; the owner approves before it merges. The routes, the screens, the distance sort and the listing location come in later changes.
- Date: 2026-11-17
- Related: ADR-013 (provider adapters), ADR-012 (search), ADR-040 and ADR-042 (search address and results), ADR-060 (listing submit without coordinates), ADR-099 (typed coordinates for localities), ADR-128 (AI chat), R-BE-09, R-BE-10, FR-GEO-01 to FR-GEO-03, DEC-19
- The owner reopened S4-T05 on 17 Nov 2026 (it was left out on 5 Nov) and answered: place lookup first, no map anywhere for now, a listing location required to submit with a locality fallback, usage tracked in the admin dashboard (calls to Ola only), no alerts, no hard ceiling that could switch place search off.

## Decision

- **One module, `src/server/places`.** `PlaceProvider.autocomplete(text)` returns suggestions already limited to the region and ordered areas first, then streets, then venues. Implementations: `createOlaPlaceProvider` (the real one), `createFakePlaceProvider` (fixed Chennai places, no network, for tests, CI and local work) and `createOffPlaceProvider` (every lookup says "off"). Features and route handlers never call Ola directly.
- **Only Places Autocomplete is called.** The owner's real-key run on 17 Nov 2026 (168 calls on a dev key) showed that every suggestion carries `geometry.location.{lat,lng}`, so Place Details (₹0.099 a call above the free tier) is not used and the `/api/places/details` route listed in `docs/ux-reference.md` is not built. Geocoding and reverse geocoding are not called either.
- **The bias is soft, so the region is enforced on the answer.** `location=13.0827,80.2707&radius=50000` is always sent and helps a lot (without it "thyagaraya nagar" found Hyderabad), but it only ranks: "Adyar" listed Karnataka first and "Bandra Mumbai" still found Mumbai. A suggestion is kept only when its point lies inside the region's bounds (the site settings, handed in by the caller) **and** its text names Tamil Nadu or Puducherry (Bangalore lies inside a rough bounding box and its text sometimes names no state). Suggestions too broad to search around (a state, a country) are dropped.
- **A suggestion's kind comes from `layer[0]`:** `borough`, `locality`, `neighbourhood`, `localadmin`, `county` are an `area`; `street` is a `street`; anything else is a `venue`.
- **`resolvePlace(text, dependencies)`** turns text into one position, a short list to choose from, nothing, or "unavailable". It first cleans the text (dots read as spaces, runs of single letters joined, so "K K Nagar" and "K.K. Nagar" become "KK Nagar", the one spelling the provider could not repair), asks the caller's own list of known places first (no cost), asks the provider, and tries a second spelling once (the assistant's own corrected one). At most two provider calls for a phrase. One area is the answer; several areas are the answer only when one is exactly what was typed; with no area, the first street or venue that holds every typed word stands for the place; anything else is a choice. A position is never guessed.
- **Failures are classified, not hidden.** A provider that cannot answer throws `PlaceLookupError` (an `UPSTREAM_FAILED` `ActionError`) with a `failure` of `timeout` (3 seconds), `quota` (HTTP 429), `error` or `off`, which the later usage count and the screens' fallback read. The message never holds the typed text, a place name or the key. The key travels in the request address, so that address is never logged.
- **Not configured is not an error.** `choosePlaceProvider` returns Ola with a key, the fake list on local and dev without one, and the "off" provider on staging and production without one. Unlike the SMS sender it never refuses to start, because a place search that cannot answer degrades to typed text and the page still works (FR-GEO-01, criterion 3).
- **A manual kill switch, `PLACES_DISABLED=1`,** makes every lookup say "off" without calling anything. It is the owner's lever if a bot burns the quota; there is no automatic daily ceiling, because a ceiling would switch place search off for everyone.
- **Nothing from Ola is stored or cached by this change,** and no Ola place id is kept (the `id` of a suggestion is only a list key). Whether coordinates may be stored for a listing (DEC-19) and whether short-term caching is allowed are questions to Ola (`OLA_EMAIL_DRAFT.md`).
- **No Ola data reaches a language model.** When the AI assistant is given place search (a later change, behind its own flag), the model returns only the place text, the server resolves it, and the model sees only homes. Ola's 2026 Platform Terms (section 6) restrict use "in connection with" an AI system; that change stayed off until Ola answered in writing. **Update 18 Nov 2026:** Ola approved in writing both the AI use and the storing of results, and the AI change is built behind `FLAG_AI_PLACE_SEARCH` (ADR-142) with this design unchanged: the model sees only the typed words and our own statuses, and nothing from Ola is stored or cached.

## Consequences

- The owner sets `OLA_MAPS_API_KEY` for dev and production separately in Vercel (one key each). The first 100,000 calls per API per month are free; above that calls are paid from prepaid credits, read in Ola's own console.
- Three variables stay as they were (`OLA_MAPS_API_KEY`, `NEXT_PUBLIC_MAP_STYLE_URL`, `FLAG_MAP_VIEW`); one is new (`PLACES_DISABLED`, in `src/server/env.ts`, `.env.example` and `docs/runbooks/environment-variables.md`).
- Tamil script is not understood by Ola's autocomplete (one test word returned nothing). A Tamil-typing visitor gets the site's own locality list; this is rechecked with more words before the search box is built.
- Not built here: the route handler, the rate limits, the usage table and its dashboard card, the search box, the distance sort, the listing location, the admin pickers, the AI tool and the map view. Each is a later change in `OLA_MAPS_PLAN.md`.

## Verification

Unit tests with a fake `fetch`: the request (address, bias, key only in the address), every failure class, the region filter (outside the box, another state, no state named, too broad), the ordering, the answer shapes, no secret in any error, the 3 second timeout; `resolvePlace` (cleanup, known places, one area, several areas, venue as the centre, a choice, nothing, the second spelling, unavailable, never more than two calls); `choosePlaceProvider` (kill switch, key, local, production without a key). The real service was exercised only by the owner's run of 17 Nov 2026.
